How the conversions work

Decimal to binary

Divide the whole part by 2 again and again, writing down each remainder, until the quotient is 0. Read the remainders from the last one up to the first. For 45: 45 ÷ 2 = 22 r 1, 22 ÷ 2 = 11 r 0, 11 ÷ 2 = 5 r 1, 5 ÷ 2 = 2 r 1, 2 ÷ 2 = 1 r 0, 1 ÷ 2 = 0 r 1, which gives 101101. For a fraction, multiply by 2 repeatedly and collect the whole-number parts from first to last: 0.625 gives 0.101.

Binary to decimal, octal and hex

Add the place values: each bit is worth a power of 2, so 1011 is 8 + 0 + 2 + 1 = 11. Bits after the point are worth ½, ¼, ⅛ and so on. To reach octal or hex, group the bits in threes (octal) or fours (hex) outward from the point and convert each group.

Two's complement

To store a negative number, write its positive value in the chosen number of bits, invert every bit, then add 1. With 8 bits, −45 is 00101101 → 11010010 → 11010011. The leftmost bit has a negative place value (−128 for 8 bits), so the range is −128 to +127. Sign and magnitude simply sets the sign bit, and one's complement only inverts the bits; both have two representations of zero, which two's complement avoids.

Binary addition, subtraction and overflow

Add column by column from the right: 0+0=0, 0+1=1, 1+1=10 (write 0, carry 1) and 1+1+1=11. To subtract B, add the two's complement of B. Overflow occurs when two numbers with the same sign give an answer with the opposite sign, because the true answer no longer fits in the available bits.

Character codes

Computers store text as numbers. ASCII gives each character a 7-bit code: "A" is 65 (1000001), "a" is 97, and "0" is 48. Unicode extends this to cover every writing system, and UTF-8 stores the first 128 code points exactly as ASCII does.

BCD

Binary-coded decimal stores each decimal digit in its own 4 bits, so 259 becomes 0010 0101 1001. It uses more bits than pure binary but converts to and from decimal digits instantly, which is why calculators and digital clocks use it.

Floating point

A floating-point number is stored as a mantissa and an exponent. In the CAPE format the mantissa is a two's complement fraction and a number is normalised when the first two mantissa bits differ (0.1… for positives, 1.0… for negatives), which gives the most precision for the bits available. Normalising 6.75: 6.75 = 0.84375 × 2³, so the mantissa is 0.1101100 and the exponent is 3. More mantissa bits give more precision; more exponent bits give a larger range.

Frequently asked questions

How do you convert decimal to binary?

Divide by 2 repeatedly and read the remainders from last to first. Fractions are multiplied by 2 and the whole-number parts read from first to last.

How do you find the two's complement of a negative number?

Write the positive value in binary, invert every bit, and add 1.

How do you know when binary addition has overflowed?

When two numbers of the same sign give a result of the opposite sign. The carry into the sign bit then differs from the carry out of it.

What is a normalised floating-point number?

One whose mantissa starts 0.1 (positive) or 1.0 (negative), so the first two bits differ and no precision is wasted on leading zeros or ones.

How is BCD different from binary?

BCD encodes each decimal digit separately in 4 bits, so 259 is 0010 0101 1001, whereas pure binary encodes the whole number as 100000011.
